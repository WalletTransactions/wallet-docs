## MODIFIED Requirements

### Requirement: Порог релевантности
Кандидаты SHALL отсекаться до слияния рангов: векторные — с косинусным расстоянием больше `kMaxVectorDistance` (константа в коде), полнотекстовые — с `ts_rank` = 0. Вопрос SHALL эмбеддиться с префиксом `search_query: `. Отказ без обращения к LLM SHALL наступать, когда порогом отсечены все кандидаты, а также когда нет ни одного полнотекстового кандидата (ни одно слово вопроса не встречается в видимых спеках; design `docs-answer-quality`, D2). Расстояние вектора и разрыв между кандидатами как сигнал «не по теме» SHALL NOT использоваться — у вопросов по теме и не по теме они пересекаются. Вопрос, у которого есть текстовый кандидат, SHALL решаться промптом («В описании системы этого нет.»).

#### Scenario: Вопрос не по теме
- **WHEN** вопрос «Какая погода в Москве?» не совпадает ни одним словом, а ни один вектор не ближе порога
- **THEN** кандидатов нет, ответ «В описании системы этого нет.», LLM не вызывалась

#### Scenario: Вопрос не по теме без совпавших слов
- **WHEN** ни одно слово вопроса не встречается в видимых спеках, хотя векторы в пределах порога
- **THEN** ответ «В описании системы этого нет.», `sources` пуст, LLM не вызывалась

#### Scenario: Вопрос не по теме с совпавшим словом
- **WHEN** вопрос не по теме имеет текстового кандидата (совпало служебное или случайное слово)
- **THEN** фрагменты передаются LLM, и отказ даёт промпт; `sources` пуст

#### Scenario: Вопрос по теме с далёким вектором
- **WHEN** у вопроса по теме есть текстовый кандидат, а ближайший вектор дальше, чем у вопросов не по теме
- **THEN** фрагменты передаются LLM, отказа до LLM нет

## ADDED Requirements

### Requirement: Контрольный набор качества
Репозиторий SHALL хранить контрольный набор из 20 вопросов (12 по `android-wallet`, 8 по системе) с ожидаемым разделом `repo/capability` для каждого и скрипт, который прогоняет набор через `POST /api/docs/ask` с токенами соответствующих платформ и печатает долю верных. Ответ SHALL считаться верным, если он не отказ и в `sources` есть ожидаемый раздел, либо если вопрос помечен как «ответа нет» и ответ — отказ. Результаты последнего прогона SHALL быть записаны в README.

#### Scenario: Воспроизводимый замер
- **WHEN** скрипт запускается на стенде с живой LM Studio
- **THEN** он выводит по каждому вопросу ответ, источники и вердикт, и итог «N из 20»

#### Scenario: Достаточное качество
- **WHEN** набор прогнан на выкаченной версии
- **THEN** верных ответов не меньше 16 из 20

### Requirement: Отказ только при отсутствии ответа во фрагментах
Если среди переданных LLM фрагментов есть спека, отвечающая на вопрос, ответ SHALL NOT быть отказом. Вопрос, на который в видимых спеках есть ответ, а `answer` — отказ, SHALL считаться ложным отказом и учитываться отдельно в замере (список переданных фрагментов API не отдаёт, признак — по ответу).

#### Scenario: Ложный отказ виден в замере
- **WHEN** у вопроса задан ожидаемый раздел, а `answer` равен «В описании системы этого нет.»
- **THEN** скрипт помечает вопрос как ложный отказ и считает их в итоге
