## MODIFIED Requirements

### Requirement: Порог релевантности
Кандидаты SHALL отсекаться до слияния рангов: векторные — с косинусным расстоянием больше `kMaxVectorDistance` (константа в коде), полнотекстовые — с `ts_rank` = 0. Вопрос SHALL эмбеддиться с префиксом `search_query: `. Отказ без обращения к LLM SHALL наступать, когда порогом отсечены все кандидаты; вопрос, у которого кандидаты остались, SHALL решаться промптом («В описании системы этого нет.»), если сервис не вводит отдельного надёжного сигнала «не по теме» (design `docs-answer-quality`, D2).

#### Scenario: Вопрос не по теме
- **WHEN** вопрос «Какая погода в Москве?» не совпадает ни одним словом, а ни один вектор не ближе порога
- **THEN** кандидатов нет, ответ «В описании системы этого нет.», LLM не вызывалась

#### Scenario: Вопрос не по теме с близкими векторами
- **WHEN** вопрос не по теме получает кандидатов в пределах порога
- **THEN** фрагменты передаются LLM, и отказ даёт промпт; `sources` пуст

## ADDED Requirements

### Requirement: Контрольный набор качества
Репозиторий SHALL хранить контрольный набор из 20 вопросов (12 по `android-wallet`, 8 по системе) с ожидаемым разделом `repo/capability` для каждого и скрипт, который прогоняет набор через `POST /api/docs/ask` с токенами соответствующих платформ и печатает долю верных. Ответ SHALL считаться верным, если он не отказ и в `sources` есть ожидаемый раздел, либо если вопрос помечен как «ответа нет» и ответ — отказ. Результаты последнего прогона SHALL быть записаны в README.

#### Scenario: Воспроизводимый замер
- **WHEN** скрипт запускается на стенде с живой LM Studio
- **THEN** он выводит по каждому вопросу ответ, источники и вердикт, и итог «N из 20»

#### Scenario: Достаточное качество
- **WHEN** набор прогнан на выкаченной версии
- **THEN** верных ответов не меньше 16 из 20

### Requirement: Отказ только при отсутствии ответа во фрагментах
Если среди переданных LLM фрагментов есть спека, отвечающая на вопрос, ответ SHALL NOT быть отказом. Пара «ожидаемый раздел есть в 8 фрагментах, а ответ — отказ» SHALL считаться ложным отказом и учитываться отдельно в замере.

#### Scenario: Ложный отказ виден в замере
- **WHEN** ожидаемый раздел входит в переданные фрагменты, а `answer` равен «В описании системы этого нет.»
- **THEN** скрипт помечает вопрос как ложный отказ и считает их в итоге
