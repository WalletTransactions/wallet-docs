# Spec Delta

## Purpose

Управление рассуждением чат-модели ответа `wallet-docs`: модели с рассуждением (например `gemma-4-e4b` в LM Studio) без отключения рассуждения тратят лимит токенов на «мысли», отвечают пустым `content` и слишком долго.

## ADDED Requirements

### Requirement: Рассуждение чат-модели настраивается

Сервис SHALL читать необязательную переменную `LLM_REASONING_CHAT`. Если она не задана, значение по умолчанию — `none`. Значение SHALL передаваться в теле `POST {LLM_URL}/chat/completions` полем `reasoning_effort` как есть, без проверки допустимых значений, кроме особого значения `off`: оно SHALL означать, что поле `reasoning_effort` в тело не добавляется. (Пустая строка в окружении, как и у остальных переменных сервиса, равна «не задано», то есть `none`.) Запросы эмбеддингов (`POST /embeddings`) SHALL не содержать этого поля при любом значении.

#### Scenario: По умолчанию рассуждение выключено
- **WHEN** сервис запущен без `LLM_REASONING_CHAT` и обрабатывает вопрос
- **THEN** тело запроса к чат-модели содержит `"reasoning_effort": "none"`

#### Scenario: Явное значение
- **WHEN** задано `LLM_REASONING_CHAT=low`
- **THEN** тело запроса к чат-модели содержит `"reasoning_effort": "low"`

#### Scenario: `off` отключает передачу
- **WHEN** задано `LLM_REASONING_CHAT=off`
- **THEN** в теле запроса к чат-модели нет поля `reasoning_effort`

#### Scenario: Пустая строка равна «не задано»
- **WHEN** задано `LLM_REASONING_CHAT=` (пустая строка)
- **THEN** действует значение по умолчанию `none`

#### Scenario: Эмбеддинги без параметра
- **WHEN** сервис считает эмбеддинги вопроса или фрагментов при любом `LLM_REASONING_CHAT`
- **THEN** тело `POST /embeddings` не содержит `reasoning_effort`

### Requirement: Ответ без рассуждения укладывается в таймаут гейтвея

При значении по умолчанию вызов LLM на запрос с 8 фрагментами SHALL возвращать непустой `content` (а не `empty_answer`) и укладываться в таймаут гейтвея на `/api/docs/*` (30 с) на штатной чат-модели контура.

#### Scenario: Вопрос на test после выката
- **WHEN** администратор задаёт вопрос через `/api/docs/ask` на контуре test с `LLM_MODEL=wallet-parse`
- **THEN** ответ приходит с кодом `200`, с непустым `answer` и непустым `sources`, быстрее 30 с
