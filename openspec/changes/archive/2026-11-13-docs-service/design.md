# Design

## Context

Стек: набор C++17-сервисов за wallet-gateway, общий код — копия wallet-common
(`util/`: jwt, jwks, jwt_claims, log, metrics, dotenv), каркас `/healthz` `/version`
`/metrics` `/openapi.yaml` `/docs` одинаков у wallet-mcp и wallet-ai. Postgres один на
контур, у каждого сервиса своя база и роль только с DML; схему и расширение `vector` заводят
инфраструктура и мигратор (wallet-infra, change `wallet-docs-assistant`). LLM — LM Studio
на хосте с одним GPU 8 ГБ. Корпус: ~4,4 МБ markdown в 11 репозиториях (~110 спек,
~370 файлов архива). Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Точные ответы по спекам на вопросы своими словами и по точным терминам (`/api/mcp/`, `aud`).
- Область документации определяется сервером; клиент её не выбирает.
- Сервис необязателен: никто от него не зависит, он ни от кого, кроме Postgres, google-auth, LM Studio.

**Non-Goals:**
- История диалога, потоковый ответ, переводы, ответы по исходному коду (только спеки).
- Вызовы wallet-ai: LLM вызывается напрямую, чтобы не было связанности.
- Бэкап индекса: он воспроизводим заливкой из Jenkins.

## Decisions

**D1. C++17, cpp-httplib, libpq, как у соседних сервисов.** Альтернатива «Python-сервис»
отвергнута по требованию владельца и ради единого каркаса, метрик и сборки.

**D2. Эмбеддинги — `nomic-embed-text-v1.5` (768 измерений) через LM Studio.** Маленькая
модель (порядка 150 МБ) помещается на GPU рядом с чат-моделью ≤ 8B Q4. Размерность
фиксируется в миграции (`vector(768)`). Смена модели означает новую миграцию и полную
переиндексацию; индекс воспроизводим, это дёшево. Альтернатива «свой эмбеддер в процессе»
отвергнута: тянет в сервис ML-зависимость. Модель требует префикса задачи: чанк
эмбеддится как `search_document: <текст>`, вопрос — как `search_query: <текст>`; смена
префиксов, как и модели, означает переиндексацию.

**D3. Точный поиск без ANN-индекса.** ~3–5 тысяч чанков × 768 float ≈ 15 МБ; полный скан
с фильтром по `repo`/`kind` укладывается в миллисекунды. HNSW добавил бы настройку и
рассинхрон при заливке без выигрыша.

**D4. Гибрид: полнотекст + вектор, слияние по рангу (RRF, k=60).** `tsv` = `to_tsvector
('russian', …) || to_tsvector('simple', …)`: русская морфология плюс точные идентификаторы
и пути. По 20 кандидатов каждым способом, лучшие 8 идут в промпт. Фильтр области — в SQL до
ранжирования, чтобы закрытые чанки не попадали даже в кандидаты. Слабые совпадения
отсекаются каждым способом до слияния: вектор — косинусное расстояние не больше
`kMaxVectorDistance` (константа в коде, 0,5; замер 2026-11-13 на `text-embedding-nomic-embed-text-v1.5`:
расстояние до ближайшего чанка у 20 вопросов по теме 0,163–0,253, у 8 вопросов не по теме
0,231–0,293 — диапазоны пересекаются, поэтому порог 0,5 ничего не отсекает: вопросы не по теме
доходят до LLM с 8 фрагментами, и отказ «этого нет» даёт промпт, а не поиск; любое значение,
отсекающее нейтральные вопросы, режет и часть вопросов по теме. Значение оставлено 0,5,
решение о смене модели эмбеддингов или ранжирования — отдельно, см. задачу 6.3),
полнотекст — `ts_rank` > 0. Без порога векторный поиск всегда отдаёт 20 «ближайших» и отказ
«этого нет» не наступает никогда; RRF порогом быть не может — он учитывает только позиции.

**D5. Таблица области — константа в коде, а не настройка.** Админ: все; `android` —
`android-wallet`/`spec`; `web` — `wallet-web`, `wallet-web-eqdefault`/`spec`; иное — пусто.
Ошибка в конфиге не должна открыть чужие спеки; тест таблицы лежит рядом. Источник
`platform` и `role` — только проверенный токен. Новый клиент = правка кода и выкат.

**D6. Заливка: эмбеддинги до транзакции, замена одной транзакцией.** Сервис считает
эмбеддинги для новых чанков (хэш содержимого, `repo`, `path`, `heading` ищется в прежнем
индексе), затем в транзакции удаляет чанки репозитория и вставляет новые. Читатели видят
либо старый, либо новый индекс. Недоступные эмбеддинги не блокируют заливку (чанк без вектора
ищется полнотекстом).

**D7. Заливка вне гейтвея, по `X-Index-Token`.** Путь `/docs/index/*` не проксируется;
Jenkins ходит по сети контура. Токен — секрет контура, сравнение за постоянное время.
Альтернатива «через гейтвей с JWT админа» отвергнута: у Jenkins нет пользовательской сессии.

**D8. Ответ: только по найденному, чанки — данные.** Системная инструкция требует отвечать
по-русски лишь по переданным фрагментам; чанки обрамляются разделителями и описываются как
данные, а не инструкции (защита от текста внутри спек). Пустой поиск не вызывает LLM.
Фрагменты нумеруются `[1]…[N]`, инструкция требует ставить номер после каждого утверждения.
`sources` — фрагменты, на которые есть ссылки, без повторов `(repo, capability, heading)`, в
порядке первой ссылки; номера вне `1…N` отбрасываются. Маркеры `[n]` из `answer` удаляются:
после дедупликации нумерация `sources` с ними бы не совпала. Нет ссылок — `sources` пуст.
Альтернатива «все переданные фрагменты» отвергнута: в источниках оказались бы 8 разделов,
из которых ответ использовал один-два.

**D9. Лимит 6 вопросов в минуту на `sub`, в памяти процесса.** Достаточно для одного
экземпляра; защищает единственный GPU. Альтернатива «Redis» отвергнута: у сервиса нет Redis.

**D10. Статус не зависит от LLM и базы.** Он говорит «раздел подключён и доступен вам»,
чтобы клиенты не мигали при кратковременных сбоях.

**Правки вне wallet-docs:** google-auth (`docs-audience`), wallet-gateway (`docs-route`),
wallet-infra (`wallet-docs-assistant`, `docs-index-upload`), android-wallet и wallet-web
(`docs-assistant`), общий код wallet-common не меняется.

## Risks / Trade-offs

- [GPU делят чат, ответы и эмбеддинги] → лимит вопросов; модель эмбеддингов маленькая;
  заливка идёт ночью/по событию, переиспользуя эмбеддинги; LM Studio выгружает неиспользуемое.
- [Модель не ставит ссылок] → `sources` пуст, ответ всё равно показывается; доля ответов без
  ссылок считается метрикой `docs_answers_without_sources_total` и в задаче 6.3.
- [Качество поиска по-русски на nomic] → проверить на 20 типовых вопросах (задача 6.3); при
  плохом результате — другая модель = миграция + переиндексация.
- [Устаревший архив даёт старые ответы админу] → у чанков есть `kind`; в промпте источник
  помечен видом, ответ ссылается на раздел; пользователям архив недоступен.
- [Текст спеки с инструкциями для модели] → D8; спеки пишет владелец, пользователь их не меняет.
- [Первая заливка 11 репозиториев долгая] → эмбеддинги пачками; повторные заливки используют
  хэши; замер 2026-11-13 на живой LM Studio (GTX 1070, nomic): `android-wallet` — 802 чанка за
  37 с, все 13 репозиториев хоста — 3678 чанков за 166 с (сумма по репозиториям), всё с
  эмбеддингами, `reused` = 0; задача 3.4.
- [Однопроцессный лимит частоты при нескольких экземплярах] → сервис один; при масштабировании
  потребуется общее хранилище (не сейчас).
