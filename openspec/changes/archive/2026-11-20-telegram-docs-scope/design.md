# Design

## Context

Telegram-бот отвечает на свободные вопросы через задание `chat` wallet-ai. Чат получает инструменты wallet-mcp и вызывает их с JWT пользователя (платформа `telegram`, выдан google-auth при привязке Telegram). Для `ask_docs` wallet-mcp меняет предъявленный JWT в google-auth на токен с `aud` `wallet-docs`, `scope` `docs:ask`, без `role`; `platform` наследуется от исходного токена (спека `token-exchange` google-auth). wallet-docs берёт область из `role` и `platform` (`scope_for` в `src/access.cpp`) и для `telegram` возвращает пустую область, то есть `403`.

Проверено по коду и спекам 2026-11-19: ни wallet-ai, ни wallet-mcp, ни google-auth, ни wallet-gateway не фильтруют `platform` на пути справки. Живой вопрос «как работает …» в Telegram ещё не задавался: пользователь Telegram получит «Справка недоступна для этого токена.» до выкатки этого change.

## Goals / Non-Goals

**Goals:**
- Пользователь Telegram получает ответ справки по любому продукту системы.
- Путь доступа остаётся прежним: `ask_docs` в чате, без новых вызовов из wallet-telegram.

**Non-Goals:**
- Не открывать Telegram внутренние репозитории (`wallet-gateway`, `wallet-infra`, `wallet-common`) и виды `change` и `archive`.
- Не менять роутинг бота, инструменты wallet-mcp и промпты wallet-ai: поведение модели (вызовет ли она `ask_docs`) — отдельный вопрос после выкатки.
- Не добавлять область «по пользователю»: она остаётся константой по `role` и `platform`.

## Decisions

**Область Telegram — все продуктовые репозитории, вид `spec`.** Решение владельца: «любые вопросы про любой продукт». Список строится от индекса test: в нём 13 репозиториев; из них закрыты `wallet-gateway` (внутренняя маршрутизация, закрыта и для MCP), `wallet-infra` (развёртывание контуров) и `wallet-common` (общий код без пользовательского поведения). Остальные десять плюс `wallet-web-eqdefault` (есть в таблице `web` и `mcp`, в индексе test пока нет) — продукты и сервисы, поведение которых пользователь может спросить: Android, веб, бот, MCP, отчёты, API, вход, ИИ, справка, сайт. Альтернатива — область «как у MCP» (веб и MCP): отвергнута, потому что вопросы про бота и приложение остались бы без ответа. Предположение для подтверждения владельцем: список закрытых репозиториев; расширить или сузить его — правка одной константы.

**Без `role` область не растёт.** `platform: telegram` расширяет область только в рамках вида `spec` и перечисленных репозиториев; админская область по-прежнему требует `role: admin` (токен Telegram `role` не несёт).

**Правка только в wallet-docs.** Таблица области — константа в коде и в спеке: меняем `scope_for`, тест `scope_table`, таблицу в `README.md`. wallet-mcp, wallet-ai, wallet-telegram, google-auth не меняются, потому что `platform` доходит до wallet-docs без искажений.

**Проверка живым вопросом в Telegram.** Критерий готовности — не только ответ `200` у `GET /api/docs/status`, но и ответ бота на вопрос «как считается баланс?» с источниками. Если модель чата не вызывает `ask_docs` на вопросы «как работает…», это отдельный change в wallet-mcp (описание инструмента); здесь он не планируется.

## Risks / Trade-offs

- [Расширение области: Telegram видит спеки сервисов, которых раньше не видел] → только вид `spec`; секретов и токенов спеки не содержат (индекс строится из OpenSpec-файлов); закрытые репозитории остаются закрытыми.
- [Длинный ответ справки не помещается в сообщение Telegram (4096 символов)] → проверить на живом вопросе; если упирается — отдельная правка бота или промпта справки, не этого change.
- [Модель чата (Qwen3-8B) не вызовет `ask_docs`] → отдельная задача после замера; область уже не будет причиной отказа.
- [Таблица области расходится с индексом: репозиторий добавили в индекс, а в область не внесли] → чанки нового репозитория для Telegram недоступны, пока константу не обновят; отказ по умолчанию безопасный.
