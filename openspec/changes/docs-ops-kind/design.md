# Design

## Context

Индекс строится из OpenSpec: `classify_path` (`src/chunking.cpp`) пропускает всё, что не лежит в `openspec/specs` и `openspec/changes`; колонка `doc_chunks.kind` ограничена `CHECK (kind IN ('spec','change','archive'))` (миграция `000001_init`); область пользователя — `scope_for(role, platform)` (`src/access.cpp`) с белым списком видов; вес вида — `search::kind_weight` (`spec` = 1.0, прочие = 0.6); метку вида для промпта даёт `kind_label` (`src/answer.cpp`). Заливку файлов делает `wallet-infra/infra/env/docs-index.sh`: он берёт только `openspec/**/*.md` репозиториев, у которых есть `openspec/`. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Вид `ops` для `README.md`, видимый только `role` = `admin`.
- Закрытие на сервере: даже если клиент заливки пришлёт чужие файлы, обычному пользователю `ops` не достаётся.
- Минимум правок: те же чанкинг, эмбеддинги и поиск, один новый вид.

**Non-Goals:**
- Не менять области `android`, `web`, `mcp`, `telegram`.
- Не индексировать исходники, `CLAUDE.md`, комментарии кода и `openspec/project.md`.
- Не вводить новые роли и права: `ops` — подмножество того, что админ и так видит.
- Правку заливки в wallet-infra здесь не делаем (см. «Другие сервисы»).

## Decisions

**D1. Один вид `ops`, а не отдельные `readme` и `plan`.** Права у них одинаковые (только админ), метка в промпте общая, вес общий. Лишний вид — лишняя строка в `CHECK`, в таблице области и в тестах. Различие README и плана видно по `path`/`capability`. Альтернатива — два вида: отвергнута, пока права не расходятся.

**D2. Что считается `ops`: только файлы с именем `README.md` любой глубины.** Границу задаёт путь, а не содержимое: сервис не угадывает, «оперативный» ли файл. Планы `org/docs/TODO_*.md` исключены по решению владельца: они описывают намерения и отложенную работу, а не действующее устройство, и ввели бы в ответы устаревшее. Альтернатива — любые `.md` вне `openspec/`: отвергнута, под неё попадают `CHANGELOG`, шаблоны `.claude/commands`, вендорные README.

**D3. Фильтр служебных каталогов на сервере.** `third_party/`, `node_modules/`, `.worktrees/`, `build/`, `vendor/` отсекаются в `classify_path` независимо от клиента. В репозиториях есть копии вендорных библиотек (`third_party/wallet-common/README.md`, `httplib`), которые зашумили бы индекс и ответы. Фильтр на клиенте заливки (`find`) дублирует его, но сервер не полагается на клиента (как с `..` в путях).

**D4. Приоритет `openspec/`.** Файл под `openspec/` классифицируется по прежним правилам (`spec`/`change`/`archive`); `README.md` внутри `openspec/` остаётся пропущенным, а не становится `ops`. Так добавление `ops` не меняет разбор ни одного файла, который индексируется сегодня.

**D5. Закрытие — в `scope_for`, а не в запросе.** Вид `ops` дописывается только в ветку `role == "admin"`; остальные ветки не меняются. Фильтр уже стоит в SQL (`kind = ANY($4)`), чужой вид до LLM не доходит. Проверка по `role`, а не по `platform`: токены MCP и обмена не несут `role` (спека `jwt-claims` google-auth), поэтому админ через MCP-токен `ops` не получит — так же, как сегодня не получает `archive`.

**D6. `capability` для `ops` — каталог файла.** Так в ссылках `sources` видно, откуда фрагмент: `infra/env`, `README`. Альтернатива — полный путь: он и так хранится в `path`; `capability` участвует в полнотексте (`tsv`), и каталог даёт лучшее совпадение, чем имя файла `README`.

**D7. Вес и метка.** Вес `ops` = 1.0, как у `spec` (и в RRF, и в `ORDER BY` SQL кандидатов). Первоначально был 0.6 как у `change`/`archive`, но замер на test (0.1.6-rc.1, 2026-11-21) показал, что при 0.6 чанки `ops` не попадали в топ-10: вклад `0.6/(60+ранг)` ниже вклада любой спеки на 10–16-м месте, а векторный поиск даёт 20 спек-кандидатов; все пять вопросов админа про развёртывание получали «В описании системы этого нет.». Админ видит `ops` один и ищет именно развёртывание, поэтому вес равен `spec`; устаревание README ограничивает метка в промпте — «справка по развёртыванию (README, может отставать от спек)», чтобы LLM не выдавала README за требование. Влияние на прочие вопросы админа проверяется набором качества (задача 5.2).

**D8. Миграция `000002`.** Снять и заново создать `CHECK` с четырьмя видами. Прежние миграции не правятся (правило проекта). Down-миграция сначала удаляет чанки `ops`, потом возвращает прежний `CHECK`. Роль сервиса — только DML; DDL выполняет мигратор, как для `000001`.

## Другие сервисы

- **wallet-infra** (отдельный change): `infra/env/docs-index.sh` — класть в тело заливки, кроме `openspec/**/*.md`, все `README.md` репозитория (без `third_party/`, `node_modules/`, `.worktrees/`, `build/`, `vendor/`). Репозитории без `openspec/` (например `org`) по-прежнему пропускаются. Порядок выкатки: сначала wallet-docs с видом и миграцией, потом заливка. Если новые файлы придут раньше выкатки, старый сервис посчитает их в `skipped` и ничего не сломается; если сервис с видом выкатить без миграции, вставка `ops` упадёт на `CHECK` (`500`, прежний индекс цел) — поэтому миграция и код выкатываются вместе.
- **google-auth, wallet-gateway, wallet-mcp, wallet-ai, клиенты** — без правок: роль уже есть в токене, `sources` отдаёт `kind` как есть.
- **wallet-common** — без правок.

## Risks / Trade-offs

- [Секреты в README попадут в индекс и в промпт LLM] → в README секретов быть не должно (значения лежат в `~/.config/wallet-secrets`); вид закрыт ролью `admin`; перед первой заливкой пройти по README поиском токенов и паролей (задача 5.1).
- [README отстаёт от кода, ответ устаревший] → метка и меньший вес в промпте; источник виден в `sources`.
- [Рост индекса: +десятки README и планов] → оценка: порядка сотен чанков при нынешних ~3700; RAM и диск пренебрежимо малы; эмбеддинги — на единственном GPU, первая заливка `ops` занимает минуты, повторная переиспользует векторы по хэшу.
- [Админ задаёт вопрос из Telegram или MCP и не видит `ops`] → осознанно (D5); для справки по развёртыванию админ пользуется web-клиентом. Расширение — отдельный change.
- [Имя файла в другом регистре (`readme.md`)] → не `ops`: правило точное, `README.md`, чтобы случайные файлы не попадали в индекс.

## Migration Plan

1. Выкатить wallet-docs с миграцией `000002` на test (rc-тег), проверить, что сервис стартует и `CHECK` принимает `ops`.
2. Залить тестовый набор README вручную `PUT /docs/index/{repo}`; убедиться, что админ видит `ops`, а `user` — нет.
3. Отдельным change включить сбор файлов в `docs-index.sh`.
4. Откат: снять `ops` из области (`scope_for`) и откатить миграцию; чанки `ops` удаляются down-миграцией, остальной индекс цел. Индекс воспроизводим заливкой.
